# Rule: Product Boundaries (trust & safety language)

HerStop is **decision support, not a safety guarantee**. This rule is non-negotiable and
applies to UI copy, docs, commit messages, and analytics labels.

## Never use (as an absolute claim about a place)
- "safe", "safe stop", "verified safe", "guaranteed safe", "crime-free", "objectively safe"
- Any phrasing that says the app "ensures" or "guarantees" safety.

## Prefer
- Recommended Stop · Good Option · Use Caution · Limited Data
- higher-confidence · better-reviewed · recent traveler feedback · area safety context
- confidence score

## Review integrity
- Never fabricate reviews, users, ratings, metrics, safety data, or locations as if real.
- Mock/demo data must be clearly marked as mock in code and docs.
- Reviews should be structured (lighting, restroom, cleanliness, staff, loitering/vibe, time of
  visit, would-stop-again, optional note), designed with moderation/reporting/privacy in mind.

## When in doubt
Describe what travelers reported and how confident the data is — do not assert a verdict.
