## 2. Dependency and risk analysis
1. **006 is the only data-destructive step.** Guard: pre-flight count of `saved_stops`/`reviews` rows on ids 1–6 must be 0 (runbook §1).
2. **The app already marks demo stops** (`isMock`, ids 1–6). After 006 they disappear; Directions is enabled for the OSM rows.
3. **Mock fallback must stay** in dev builds (project rule). Release builds already refuse invented stops.
4. **App ↔ schema coupling:** the app calls `get_stop_reviews`, `get_stop_review_stats`, `report_review`, `hide_review` (003) and `delete_my_account` (007). Until applied these paths return errors by design.
5. **OTP delivery:** Supabase's default mailer is team-only and rate-limited; non-team testers need custom SMTP (Resend, domain required). Founder action; blocks sign-in tests for anyone except the founder.
6. **Data licensing:** OSM-derived rows require "© OpenStreetMap contributors" wherever shown (already present; note it also appears on demo stops — fix in a later UI pass).
7. **Privileged key:** nothing in this plan needs a privileged server key in the app or in agent hands. SQL is run by the founder in the SQL Editor.

## 4. Backup and rollback plan (for `herstop`)
- **Before:** record the pre-state: `select id,name from stops order by id;` and counts for `saved_stops`, `reviews`, `profiles`; export `stops` to CSV from the dashboard (Table Editor → export). Capture `pg_policies` and the function list for the public schema. Dashboard backups/PITR depend on the plan tier — **verify the tier; do not assume**. A full dump needs the database password, which is a privileged credential and is not handed to agents.
- **Because the tables are near-empty**, data-loss risk is low; schema reversibility matters more.
- **Rollback scripts to write and test (new files, reviewed, not applied):** `003_down` (exists in docs), `005_down` (drop added columns/index/trigger — only if no later code reads them), `006_down` (delete `source='openstreetmap'` rows, re-insert the 6 seed rows), `007_down` (`drop function`).
- **Order of undo:** 007 → 006 → 005 → 003. Each migration is already wrapped in `begin…commit` with a 5 s `lock_timeout`, so a failed run leaves no partial state.
- **Stop conditions:** pre-flight non-zero on real data; any `rls:check` regression; unexpected row counts.

## 7. Sprint 3 — nationwide discovery (after Sprint 2 is green)
1. ZIP/city fallback: Census gazetteer loaded into a small public-read table + prefix search (no third party).
2. Address search: local Expo module around Apple `MKLocalSearchCompleter` (see `docs/research/search-autocomplete.md`).
3. Geographic stop query: PostGIS `stops_near` (radius and row limit capped). **Needs approval** because it sends a search *centre*; default to a rounded centre for searched places and keep device-distance sorting on the phone.
4. Expand ingestion beyond the I-65 corridor via the existing script (ODbL attribution kept).
5. Accuracy/privacy trade-offs of coarse queries to be documented with measured error before shipping.

## 8. Parallel low-risk track — crime-data proof of concept (local only)
Chicago open-data CSV (public, no key) read by a local script; compute counts by category within a radius of
sample points; output coverage/limitations. **No database writes, no app changes, no score.** Report source
quality, reporting lag, missing coverage, and false-precision risks.
